ConnectNodes
  Call: {"identifiers":["AAECAwQF","AAECAwQG","AAECAwQH"]}
  Requires at least two distinct identifiers whose complete contents are loaded. Identifiers may be canonical eight-character IDs or pending IDs created in this session. It stages every supplied node as a recent connection of every other supplied node in the session's read-your-writes transaction plan.

ConsolidateFanout
  Call: {"parentIdentifier":"AAECAwQF","aggregatorIdentifier":"AAECAwQG","fanoutIdentifiers":["AAECAwQH","AAECAwQI"]}
  Requires complete parent and aggregator nodes. It stages removal of the named recent connections from the parent, retains the aggregator under the parent, and places the named connections under the aggregator. The database itself imposes no connection-count policy.

SetFixedConnection
  Call: {"parentIdentifier":"AAECAwQF","childIdentifier":"AAECAwQG","slot":1}
  Requires complete parent and child nodes and a positive contiguous slot number. Fixed connections are arbitrary placements under Kennedy's control and have no priority or task meaning. It stages replacement of that directional slot. Use the string "blank" as childIdentifier to clear the slot.

CreateNode
  Call: {"parentIdentifiers":["AAECAwQF","AAECAwQG"],"ownerIdentifier":"AAECAwQH","shortName":"New Memory","shortDescription":"Short description.","longDescription":"Complete durable knowledge."}
  Requires one or more distinct, fully available parent nodes and a fully available owner. It stages a node and returns a stable session-local ID such as pending:47. Later staged operations may use that pending ID. The short name is 4–50 characters, the short description is at most 200 characters, and the long description is at most 1000 words.

UpdateNode
  Call: {"identifier":"AAECAwQF","ownerIdentifier":"AAECAwQH","newShortName":"Updated Memory","newShortDescription":"Updated description.","newLongDescription":"Complete updated durable knowledge."}
  Requires a fully available canonical or pending node and a fully available owner. It stages replacement of all three descriptive fields and the owner in the session's read-your-writes plan. Nodes shown as unowned must be assigned an owner when updated. The same field limits as CreateNode apply; omitted prior text is removed.

All Kweb mutations remain local and recoverable until the session completes. History ingress commits the complete session archive, supplied objects, node creates, node updates, and connection changes through exactly one Kweb transaction. Tool success before that final commit means “staged,” not “already visible globally.”

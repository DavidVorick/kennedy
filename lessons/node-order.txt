Node rendering and ordering rules

Terminology

A directly loaded node is a node explicitly loaded into the session, including the
session's automatically loaded root nodes.

A fixed node is a fixed connection of a directly loaded node.

An active node is one of the first eight recent connections of a directly loaded
node. Recent connections after the first eight are fanout connections. The
eight-connection distinction is a presentation rule, not a database limit.

Role precedence

Each node receives at most one full-node box. If the same node qualifies for more
than one role, the roles have this precedence:

1. Directly loaded
2. Fixed
3. Active

For example, a node that is directly loaded and is also a fixed connection remains
a directly loaded node. A node that is both fixed and active is rendered as fixed.
It is never given another full box for its lower-priority role.

Full-node boxes

Full-node boxes are rendered in three groups:

1. All directly loaded nodes, in direct load order.
2. All unique fixed connections of the directly loaded nodes.
3. All unique active connections of the directly loaded nodes.

Within the connection groups, traversal follows the order of the directly loaded
nodes and then the connection order stored on each node. Duplicates and nodes
already represented by an earlier group are skipped.

Every full-node box contains exactly:

- Node ID
- Node name
- Node summary
- Node long description
- Fixed connection IDs
- Active connection IDs
- Fanout connection IDs

Connection lists in a full-node box contain IDs only. They do not inline names,
summaries, descriptions, ownership, timestamps, object references, or other
metadata.

Pending nodes created during the session are displayed as staged full-node boxes
after the directly loaded nodes and before the fixed-node boxes. Their active and
fanout lists use the same first-eight split.

Directly loaded node fanout boxes

After all full-node boxes, each directly loaded node receives one fanout box. That
box contains the ID and summary of each otherwise-unrepresented fanout connection
of that directly loaded node.

These boxes follow directly loaded node order. Before processing them, every node
that received a full-node box is marked as already represented. After a fanout
entry is emitted, it is also marked as represented. Consequently:

- A full node never reappears as a fanout entry.
- A fanout connection shared by multiple directly loaded nodes appears only in
  the first applicable fanout box.
- Every directly loaded node still receives its fanout box when it has no
  remaining entries; the box displays "None."

Aggregate connection boxes

Three aggregate boxes follow the directly loaded node fanout boxes:

1. Fixed-node connections

   Contains the unique fixed and active connections of all fixed nodes. Each entry
   displays node ID, node name, and node summary. Fixed nodes are traversed in
   their established order; for each fixed node, its fixed connections are
   considered before its active connections.

2. Active-node connections

   Contains the unique fixed and active connections of all active nodes. Each
   entry displays node ID, node name, and node summary. Active nodes are traversed
   in their established order; for each active node, its fixed connections are
   considered before its active connections.

3. Fixed-and-active-node fanout

   Contains the remaining unique fanout connections of every fixed and active
   node. Fixed nodes are traversed first, followed by active nodes. Each entry
   displays only node ID and node name.

All three aggregate boxes are present even when empty, in which case they display
"None."

Global deduplication

One global represented-node set is shared across the entire rendering pass. It is
initialized with every full node and is then carried through:

1. The fanout box for each directly loaded node
2. The fixed-node connection aggregate
3. The active-node connection aggregate
4. The final fixed-and-active-node fanout aggregate

Once a node has been represented in one of those places, later places omit it.
This prevents the same node's descriptive entry from being rendered twice.
Connection IDs inside a full node's connection lists remain references, so an ID
may naturally also be the Node ID of the referenced node's own full box.

Box identity and reordering

Changing a node's role or rebuilding the layout should reuse its existing active
box whenever possible. Display order is maintained separately from append-only
event history, so boxes can move into the required presentation order without
rewriting history or changing their identities. Boxes that no longer belong in
the layout are retired. If a retired logical box is needed again later, a new box
generation is created because retired boxes are never reactivated.
